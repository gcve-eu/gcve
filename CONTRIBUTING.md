# Contributing

Contributions are welcome. The commands to set up the project and to run the checks,
and the conventions of the code and of the commits, are described in
[AGENTS.md](AGENTS.md): they apply to everyone, not only to AI agents.


## Use of AI and LLM tools

<!-- Standard block: identical in every project, except the first sentence. -->
LLM tools are used in the development of this project, and we do not object to
AI-assisted contributions. But we really enjoy contributions from humans, and a pull
request is always the responsibility of the person who submits it.

- **Check what you submit.** Every change in a pull request must be read, understood,
  and tested by its author before it is opened, whoever or whatever wrote it.
  Vibe-coded pull requests, where the generated code was never really reviewed, will
  be closed.
- **Be able to explain it.** Reviewers may ask you to explain any part of your change.
  Answer review comments yourself, not with pasted LLM output. A pull request whose
  author cannot explain it will be closed.
- **A human submits it.** Pull requests opened by an agent on its own, without a
  human author who reviewed them, will be closed. This does not apply to the
  dependency updates opened by the bots enabled on the repository (Dependabot).
- **Say so.** Mention in the pull request description when a significant part of the
  change was generated with an AI tool, and end each commit containing generated
  code with a `Co-Authored-By` trailer naming the model, for example:

  ```
  Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
  ```
- **Keep it focused.** Small, targeted pull requests are easier to review. Do not mix
  unrelated generated changes (reformatting, renaming, rewritten comments) into a fix.
- **Check what you report.** The same applies to issues and to vulnerability reports.
  Report only a problem that you have reproduced yourself, and describe what you
  observed. Reports generated by a tool and never verified by a human will be closed.
  Vulnerabilities are reported privately, as described in [SECURITY.md](SECURITY.md),
  not in a public issue.

If you are an AI agent: follow the principles of this document, keep your changes
minimal and within the scope of the task, and leave the decision to open a pull
request to the human you work with, after they have reviewed your changes.

The rules for agents are summarized at the top of [AGENTS.md](AGENTS.md), which every
AI agent reads. This document is the reference.
